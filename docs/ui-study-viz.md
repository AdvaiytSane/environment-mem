## 1. Twenty rules

Each rule is a test you can run against the page. The source follows in brackets.

### Type

**1. Two faces, each with one job.** The UI sans (Inter) carries prose, names and headings. The mono (Geist Mono) carries anything a machine produced: paths, commands, tool names, numbers, timestamps, the ticker. If a string could appear in a terminal, it is mono. Test: no path or number is set in Inter, no sentence is set in mono except captions that quote a command. [Raycast DESIGN.md: "Monospaced type is used as an accent for commands, shortcuts, code-like values, and anything that should read as machine." Vercel Geist typography: `text-label-13-mono` "used to pair with Label 14, as the smaller mono size looks better".]

**2. Tabular figures in columns, proportional figures on a standalone number.** Table cells, axis ticks and the lane counters get `font-variant-numeric: tabular-nums` so digits line up. A lone big number (the delta callout, a hero stat) uses the font's default figures, because equal-width digits make `121` look loose at 22px and up. Test: `tabular-nums` appears only on `table`, tick labels and counter spans. [dataviz `references/marks-and-anatomy.md`: "Proportional figures for big numbers; tabular only in columns." Vercel Geist typography: "Tabular is used when conveying numbers for consistent spacing."]

**3. Text never wears the data colour.** Labels, values, legends and captions stay in the text tokens (`--fg`, `--muted`, `--subtle`). Identity comes from a coloured dot or strip beside the text, never from colouring the text. The one exception is a label inside a filled shape, which picks white or ink by the fill's luminance. Test: no `<text>` or span has `fill` or `color` set to a shape hue. [dataviz `SKILL.md` non-negotiables: "Text wears text tokens, never the series color." Same in `references/marks-and-anatomy.md`.]

### Colour

**4. Grey surfaces, one accent, and the accent has one meaning.** Every surface, line and text tier is a grey with an alpha. One hue (sky, `#38bdf8`) is the accent and it means exactly one thing on this page: "headstart, the thing to look at". Interaction states (hover, selected, focused) use white or a lighter grey, not the accent, so the accent never has to mean two things at once. Test: list every use of `--accent` in app.css and the js files and write one word next to each; if the words differ, the rule is broken. [Linear redesign post: they reduced chrome colour by "limiting how much chrome (blue in our case) was used" for a "more neutral and timeless appearance". Linear DESIGN.md: "Reserve lavender ONLY for: brand mark, primary CTA, focus ring." Vercel (shadcn.io/design/vercel): "There is no brand-blue or marketing accent, the ink IS the brand." Status colours (red for a failed run, amber for a warning) are separate from the accent and from the categorical set, and always ship with a label or icon, never colour alone: dataviz `references/palette.md`, "Status palette (fixed, never themed)".]

**5. Categorical hues in a fixed order, capped, never cycled.** Shapes take hues in a fixed slot order. The first three slots are safe for every pair in both light and dark; past three, extra shapes fold into "other" (grey) or get their own small multiple. A seventh shape never gets slot one again at lower alpha. Test: `shapeColor(n)` for n greater than the cap returns grey, not a repeat. [dataviz `SKILL.md`: "Assign categorical hues in fixed order, never cycled. A 9th series is never a generated hue." dataviz `references/palette.md`: "the first three slots validate all-pairs in both modes... Past three, fold to Other or facet." Observable's palette post: the first two colours are blue and orange because "their high difference in both a* and L* make them easily discriminable for viewers with both typical vision and most forms of color vision deficiency."]

**6. The heatmap is one hue, light to dark, and the legend says which end is "same".** A distance matrix is a sequential scale: one ramp from surface to full ink. The lightest step may sink into the surface, because it means "nothing here". The scale bar carries both end values and the word for each end ("0.2 same" and "0.8 unrelated"), so no one has to guess whether bright means close or far. Test: the legend has a word at both ends, not only a number. [dataviz `references/palette.md`, "Sequential hue": "the lightest step means near zero and is allowed to recede toward the surface." dataviz `references/anti-patterns.md`: "Rainbow / non-neighbor sequential... Good: One hue, light to dark." dataviz `references/choosing-a-form.md` line 22: "Compare magnitude, low to high: heatmap for a grid, sequential (one hue)."]

**7. A colour keeps its meaning across every view and every second of the animation.** If a shape is mint in the graph, it is mint in the matrix strip, in the legend, and in the lane that belongs to it. If grey means "not yet explained" in step 1 of the reveal, grey never means "cold arm" in the same frame. Test: pick one hue, walk all four tabs and the drawer, and say its meaning in each place; it must be the same word. [Grant Sanderson, Perell podcast: he keeps visuals stylistically consistent so "the viewer's brain can hopefully see a connection more readily than if it was more stylistically inconsistent." manim colours rule file: "Use the same colors for related concepts." dataviz `references/anti-patterns.md`: "Recolor-on-filter... Color follows the entity, not its row number."]

### Density

**8. The chrome is an inverted L; the stage is the content.** Top bar and left rail hold search, tabs, legend, inspector and status. The stage holds one view at a time and nothing else. Nothing in the rail is a chart. Nothing on the stage is navigation, except the step buttons that drive the stage itself. Test: every control lives in the top bar, the rail, or the drawer head. [Linear redesign post: the "inverted L-shape" is "the global chrome of the application that controls the content in the main view."]

**9. Density comes from removing things.** Before reducing a font size or a padding, delete something. Candidates in order: redundant labels, boxes around things that a gap already separates, a second copy of a number that is already in the table, decorative rings and glows. Test: for each pixel of ink on the stage, ask what data it encodes; if the answer is "none", it goes. [Tufte via jtr13.github.io: "Above all else show data. Maximize the data-ink ratio. Erase non-data-ink. Erase redundant data-ink." Linear DESIGN.md: "The dark canvas IS the whitespace"; the LogRocket summary of Linear's look: "information density that never feels crowded because everything non-essential is absent".]

**10. Hairlines, solid, one step off the surface. No shadows.** Gridlines, axis rules, table row dividers and panel borders are 1px solid at a low white alpha. Depth is a surface step (`--surface`, `--surface-2`) plus a hairline, never a drop shadow, never a dashed line. Test: grep app.css for `box-shadow` and `dashed`; the only dashed stroke allowed is the "wrote" edge in the graph, because there dashing encodes a different edge kind. [dataviz `references/marks-and-anatomy.md`: gridlines are "one-step-off-surface gray, hairline (1px), solid (never dashed), recessive". Linear DESIGN.md: "No drop shadows; depth via surface ladder + hairline borders." Raycast DESIGN.md: hairline `#242728` as the "1px universal card edge".]

**11. One crowded chart becomes small multiples with one shared scale.** The per-task view is one column per task, all columns on the same y axis, so the eye compares heights directly. A live pair appends a column on the same scale, never a new chart. Never two y axes on one plot. Test: count `y` scales on the sessions view; the answer is one. [Observable Plot facets doc: "Faceting partitions data by ordinal or categorical value and then repeats a plot for each partition, producing small multiples for comparison"; facets share position scales. Tufte via jtr13: small multiples. dataviz `SKILL.md`: "One axis. Never a dual-axis chart."]

### Tables with uncertainty

**12. Every interval says what it is, and the table says n.** A header reads "cost per session, mean, 95% CI, n=18", not "cost". A cell reads `0.394 ±0.031` with the ± in the muted tone, or `0.36 to 0.43`. The statistic (sd, se, 95% CI) is named once in the header or the note, never left for the reader to guess. Test: cover the note and ask a stranger what the small grey number means; if they cannot say, the header is missing a word. [Wilke, Fundamentals of Data Visualization ch. 16: "Whenever you visualize uncertainty with error bars, you must specify what quantity and/or confidence level the error bars represent." PLAN.html: "at n=18 the interval on the cost delta is about the size of the effect, so '7 to 12%' is the honest range, not a point."]

**13. The delta column leads and is the only coloured column.** The first numeric column after the arm name is the change against cold, as a signed percentage. Raw means sit to its right in the muted tone. The delta gets the accent when it moves in the good direction and stays grey otherwise; a good-direction colour never appears anywhere else in the row. Numbers are right-aligned, tabular, one decimal at most. Test: exactly one column in the table has any colour. [dataviz `references/marks-and-anatomy.md`, stat tile contract: "delta (optional; signed, vs a named period; color = direction x whether up is good)". Vercel Geist typography on tabular figures for numeric columns. The memory rule "lead with percentages" in `~/.claude/projects/-Users-nikhilkrishnaswamy/memory/feedback_lead-with-percentages.md`.]

**14. Every chart has a table twin, and a tooltip never gates a value.** The graph, the matrix and the sessions view each have a way to read every number without hovering: the Measured tab for the runs, the inspector's neighbour list with distances for the graph, a sorted pair list for the matrix. Hover adds speed; it never adds facts that exist nowhere else. Test: unplug the mouse and try to read the ncd between two named sessions. [dataviz `references/anti-patterns.md`: "A tooltip as the only way to read a value... Tooltips enhance, never gate" and "Every chart has a table-view twin."]

### Tickers

**15. A ticker is a stack of blocks.** A session is one block: a prompt row at the top (the header), one row per tool call, the injection receipt right under the prompt, a stop row at the bottom with the count. The block head stays pinned with the running counters (calls, calls before the first edit, seconds) so the numbers are readable while rows stream past. A run that ends badly (non-zero exit, tests fail) gets a red bar on the left of the block and the word "failed" in the stop row, never colour alone. Test: with 200 rows in a lane, the counters are still visible without scrolling. [Warp block basics: "Blocks group commands with their output together"; "Warp keeps the Sticky Command Header pinned at the top that displays the command the Block corresponds to"; "Blocks that quit with a non-zero exit code have a red background and red sidebar."]

**16. Rows enter with one short motion, and nothing else moves when a row lands.** Each new row fades from 0.2 to 1 and rises 2px over about 280ms with the page's one easing curve. The graph, the counters and the caption do not animate in response. A refetch or a re-render holds the previous frame at reduced opacity rather than blanking. Test: record 5 seconds of a live run and check that only the newest row and the counter digits change. [manim building blocks: "animations are procedures that interpolate between two mobjects", default run time 1 second, and the scene waits between plays. dataviz `references/anti-patterns.md`: "Skeleton flash on refetch... Hold the previous render at reduced opacity, no layout jump." Raycast DESIGN.md: "rows are tight, line-height is controlled".]

### Heatmaps

**17. Order the matrix so the structure is a block, and keep the categorical colour on the margin only.** Rows and columns follow community order, so a community is a dark square on the diagonal and a shape is a lighter square around it. The shape colour appears only as a strip along the top and left edges. Cells stay on the one-hue ramp. Each cell is its own hit target and its tooltip shows both session names and the distance to three decimals. Test: shuffle the order and the picture should turn to noise; that is the proof the order carries the meaning. [matrix.js header comment, which already states this. dataviz `references/interaction.md` lines 15 and 16: "On bars and cells, the mark is the hit target... each heat-cell carries its own tooltip showing category and value." Observable Plot's "What is Plot" cites Bertin, whose reorderable matrix is the origin of the rule.]

### Staged animation

**18. One idea per moment, then wait.** A step changes one thing on the stage, the caption names that one thing in 25 words or fewer, and nothing else moves until the caption has been readable for about three seconds. The step sequence is: nodes; edges; hulls; hull colour; the new arrival. Never two of those at once. Test: pause the reveal at any frame and name the single thing that is different from the previous frame. [manim `MovingFrameBox` example: `self.play(Create(framebox1))`, `self.wait()`, `self.play(ReplacementTransform(framebox1, framebox2))`, `self.wait()`. 3Blue1Brown SoME criteria: clarity means "jargon should be explained, the goals of the lesson should be understandable with minimal background". The attention lesson: "We'll begin by describing a single head of attention, and later we will see how the attention block consists of many different heads running in parallel."]

**19. Interpolate between states, and never animate a step that has no meaning.** When a node goes from grey to mint, the fill interpolates. When the highlight goes from node A to node B, it travels. When nodes go from "arrived in time order" to "placed by distance", their positions interpolate, because that motion is the distance doing its work. What must not move is the force simulation settling on its own: pre-tick it until it is still, then reveal. Settling jitter is a fictional step that says "the physics is the point", and it is not. Test: during the reveal, no node moves unless the caption is about why it moves. [manim building blocks: `Transform` maps one mobject's points onto another's. Grant Sanderson, Perell podcast: "the information of a function doesn't require steps in between" and adding fictional steps might lead viewers to think "the way the grid moves is somehow important."]

**20. The camera follows the point, then restores.** When the new session arrives, the frame scales toward it and moves with it while its edges draw; when the moment is over the frame returns to the full view. Every other step keeps the camera still. The rail, top bar and drawer never move at all; they are the fixed frame that makes the stage's motion readable. Test: count camera moves in the 60 seconds; the answer is two, in and out, both in the last beat. [manim `FollowingGraphCamera` example: `self.play(self.camera.frame.animate.scale(0.5).move_to(moving_dot))`, an updater keeps the frame on the dot, then `self.play(Restore(self.camera.frame))`.]

## 2. Storyboard: a 60-second reveal

Five beats: sessions, distance, communities, shapes, a new session arrives. The stage is the graph view. The top bar, the rail and the drawer never move; they are the frame. The caption sits top centre in one fixed box and changes text only; it never slides. Captions are 25 words or fewer, so each is readable in about 3 seconds, and every beat holds still for at least that long after its last motion. One easing curve everywhere: `cubic-bezier(.2, .7, .2, 1)` from tokens.css.

Before the first frame: run the force simulation to rest off screen (graph.js already ticks 160 times), record the settled position of every node as `P_settled`, and compute a second layout `P_time`: nodes on a wide arc across the stage, ordered by the time they were recorded. The reveal moves between these two frozen layouts. The simulation never runs while the camera is on.

Notes on the beats:

- The first caption carries the reason to care in the first three seconds, before any node appears. [3Blue1Brown SoME criteria: "It should be clear to the reader/viewer within the first 30 seconds why they should care."]
- Distance is shown twice on purpose: once for one node, close up, so the reader learns what an edge is; then for all nodes at once. The attention lesson does the same, one head first, then 96. [https://www.3blue1brown.com/lessons/attention/]
- The only motion of positions is the travel from time order to distance order, and it is the meaning of the beat. Nothing drifts before or after. [Grant Sanderson, Perell podcast, on fictional intermediate steps.]
- Colour arrives last, after structure, so the reader has already seen the groups as grey shapes before a hue is attached. This is the dataviz skill's order too: form first, colour last. [dataviz `SKILL.md`: "Color comes LAST. Most bad charts pick colors first."]
- The camera moves exactly twice: in for the one-node close-up at 0:12 and back at 0:15; in for the arrival at 0:48 and back at 0:57. [manim `FollowingGraphCamera`: scale and move_to, updater, Restore.]
- What the current graph.js `play()` does differently: a fixed 4200ms per step regardless of caption length, captions of up to 40 words, the simulation still ticking during the sessions step, and no camera move on arrival beyond the `focus` zoom. The storyboard replaces the fixed timer with per-beat durations and a hold after each.

## 3. The three mistakes an amateur makes on a page like this

**Mistake one: everything moves at once.** The force layout jitters while nodes fade in, the ticker rows slide, the pulse ring expands, the caption fades, the counters tick, all in the same second. The reader cannot tell which motion is the message, so none of them is. On this page the risk is concrete: `graph.js` keeps the simulation ticking with `alphaDecay(.03)` after `setData`, so nodes drift for several seconds after load, and `play()` fires the next step on a timer whether or not the previous step has settled.

How to avoid it: pre-tick the simulation to rest and freeze positions; animate one property per beat (opacity, then edge draw, then position, then colour); put a hold after every beat; let the ticker be the only thing that moves while a run is live, and never run the reveal and a live run in the same minute. [manim `MovingFrameBox`: play, wait, play, wait. Grant Sanderson on fictional steps, Perell podcast. dataviz `references/anti-patterns.md`: "Skeleton flash on refetch... no layout jump."]

**Mistake two: colour for decoration.** Six categorical hues that cycle when a seventh shape appears, red and amber used as series colours and also as status colours, the accent used for the selected tab, the focused input, the headstart lane, the `write` rows, the `inject` rows, the delta, the new node, the matrix hover, and the mean line in the timeline. When one hue means nine things, it means nothing. `shared.js` does the cycling (`SHAPE_COLORS[(sid ?? 0) % 6]`), `tokens.css` lists `--acc-red` and `--acc-amber` in the same list as the shape hues, and `app.css` uses `--accent` for interaction and identity both.

How to avoid it: greys for everything structural; one accent with one meaning (headstart, the thing to look at); interaction states in white and lighter greys; shape hues in a fixed order, capped at the count that passes the validator (three, per `references/palette.md`), with the rest folded to grey; status colours reserved for failure and warning and always paired with a word. Run `node /private/tmp/claude-501/bundled-skills/2.1.278/87ad5594062d52ab5713fa4b11da21f1/dataviz/scripts/validate_palette.js "#38bdf8,#3ddc97,#b7a6ff" --mode dark --surface "#0a0a0b"` before keeping any set. [dataviz `SKILL.md` non-negotiables. Linear DESIGN.md: reserve the accent for three uses. Observable's palette post on ordering hues by how far apart they read.]

**Mistake three: numbers without their conditions.** A "-9%" with no n, a mean with no interval, an interval with no name (sd? 95% CI?), a value that lives only in a tooltip, a percent next to a raw count with different decimals. On this page the Measured table shows the spread in an 11px faint span (`td .sd`) that the header never explains, the sessions view shows per-task deltas with no n on the chart, and the matrix's ncd values are readable only on hover. PLAN.html already knows the honest form: "at n=18 the interval on the cost delta is about the size of the effect, so '7 to 12%' is the honest range, not a point."

How to avoid it: the table header names the statistic and n once; the delta column reads as a range when the interval is as wide as the effect; every chart has a table twin; the tooltip repeats what the twin shows and adds nothing that exists nowhere else; one decimal for percentages, none for counts. [Wilke ch. 16: "you must specify what quantity and/or confidence level the error bars represent." dataviz `references/anti-patterns.md`: "A tooltip as the only way to read a value." PLAN.html, Results section.]
