Headstart Results

What was run on 19 September 2026, what came out, and whether it is good.

What headstart is

A coding agent (Claude Code, Devin) spends the first part of every job finding out how the repo works: how to run tests, where routes get registered, which table a flag goes in. Headstart records what one session did, boils it down to a short list (files it changed, what verified it), and hands that list to the next session before it starts. The next session should need fewer steps.

What was run

  • One test repo: a 125-file Node service we built, with a test suite and three planted bugs.
  • Nine tasks on it: add 3 CLI flags, add 3 endpoints, fix 3 bugs. Each task has a hidden test that says pass or fail.
  • Each task run 2 times under each of three conditions, in a fresh copy of the repo:
    • cold: the agent gets nothing.
    • headstart: the agent gets what earlier sessions on other tasks recorded. Never its own task.
    • hand-written doc: a person wrote a 28-line file explaining the repo. This is the thing headstart is competing with.
  • Two agents: Claude Code and Devin CLI, both on the Sonnet model. 54 runs each, 108 in the clean set. About 200 more runs earlier in the day while the harness was being fixed, not counted.
  • Measured per run: tokens read, tool calls, seconds, dollars, test pass or fail.

Good or bad

Good: it works, on two different agents, with nothing written by a person, and it never broke a task. A quarter fewer tokens read is a real saving at fleet scale.

Not as good as a person: a human's 28-line doc beats it on every number. The doc says why ("a route only takes effect once it is in ROUTES"). The recording only says what ("src/registry.js changed in 6 of 6 endpoint tasks"). The agent still reads to find the why.

One thing that got worse: calls before the first edit. Agents given a head start check the claims before acting, so they read a bit more up front, then save on everything after.

One confound found and fixed mid-day: another memory hook on this laptop was quietly helping the cold runs. With it off, the effect roughly doubled. The numbers above are the clean ones.

Ideas for improvement

  • Turn "what changed together" into a sentence with a reason. The gap to the human doc is the why. A one-line explanation per rule, generated from the verify command's output, is the next experiment.
  • Only name a file when most matches agree. Done after the audit; one task had lost 10 calls chasing a file that one of three matches touched.
  • More repeats. 18 per cell gives a wide interval. 3 repeats on the two arms that count would halve it for about $25.
  • Bigger repo. Discovery cost grows with repo size; the fixture is 125 files. A 2,000-file repo would show a bigger gap between cold and headstart.
  • Learn from warm runs too. Only cold runs write memory today, so memory only ever comes from the worst sessions.
