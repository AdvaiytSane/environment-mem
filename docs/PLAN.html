What the three rounds say. A recorded procedure handed to the next session cuts tool calls by about a tenth and cost by 7 to 12%, with nothing written by hand. A person's four-line repo doc still does twice that. The doc carries the mechanism ("a route only takes effect once it is in ROUTES in src/registry.js"); the recording carries the co-change ("src/registry.js changed in 6 of 6 endpoint tasks"), and agents re-read to find the mechanism. Round 2 rewrote injection as counted rules and did not close the gap. Round 3 wrote the same content as a repo file and did worse than hook injection, so the channel is not the reason either. Calls before the first edit went up in every injected arm: the agent checks the claims before acting.

Devin CLI runner, free model, 66 clean runs: procedure injection -10% context tokens, -5% tool calls; doc arm mixed; facts arm worse. High variance and a quota-skewed sample, not for a slide. Rerun on a paid model when usage is back.

What that means for the pitch

  • Cognition table: "sessions two onward run about 10% fewer tool calls and 7 to 12% cheaper on this repo, no human-written docs, tests still pass". Then the doc row, unprompted: a person's doc does 25%, and the two stack in principle. Show the table, then the live run.
  • Token Company: the memory layer makes no model call. Recall and extraction are deterministic; the only LLM cost in the product is the agent's own session, which is what shrinks.
  • Fleet row stays labelled as a projection with its interval. At $0.39 a session on sonnet the fleet saving is hundreds of dollars per 9,000 sessions; the ACU-minutes column is what Devin bills in.

What it is

headstart is a CLI that sits under Devin CLI, Claude Code and Codex through their hook files. It records what a session actually did (commands run, files read, files written, what verified the result), turns that into a short procedure, and hands the procedure to the next session on the same repo before its first prompt. The next session skips discovery: no re-reading the build setup, no re-finding where things live, no re-learning how to run tests.

The product on screen is a table, not a memory browser: tokens, tool calls, seconds and cost per session, cold against warm, and the same delta multiplied by a fleet.

Why Devin cares

Devin's person said: not memory, savings. Nine thousand VM sessions, and what happens to context. Every one of those sessions on the same repo repeats the same discovery in its own context window. That discovery is the most expensive and least useful part of the trace. Warm start removes it from sessions two through nine thousand.

So the pitch leads with the saving and the context. Memory is the mechanism, named once. If the number holds, memory is the thing they will want after all.

How it works

capturePostToolUse and Stop hooks append each tool call to a per-session trace. Devin CLI reads Claude-format hook files, so one hook file covers Devin CLI, Claude Code and Codex. Warp has no hooks: capture there is oz run conversation get or a manual export, recall is the skills file.
extractDeterministic. Trace in, procedure out: ordered steps grouped by read, search, write, execute; preconditions (what was read before the first write); postconditions (the command that verified it). No model call.
injectSessionStart gets repo facts (verify command, entry files, hub files). UserPromptSubmit gets the one procedure that matches the prompt. Both as additionalContext, wrapped as reference data. skills writes the same procedures as SKILL.md for harnesses without hooks (Warp) and for cloud Devin.
measureEach session's usage, tool-call count, duration and test result land in a results file. headstart report prints the table and the fleet projection.
headstart install              # .claude/settings.json hooks (Devin CLI reads the same file), ~/.codex/hooks.json
headstart hook <Event>         # stdin: hook event. appends trace, extracts on Stop, injects on start and prompt
headstart recall "add a flag"  # the procedure a prompt would receive
headstart skills               # .agents/skills/*/SKILL.md (Devin, Warp, Codex) and .claude/skills/*/SKILL.md
headstart eval --runner claude --repeats 2
headstart report results/<dir>  # table, fleet projection, console.html

Store is a local JSONL file written this weekend.

Eval design

  • Fixture: a 120 to 180 file Node service with a test suite and a non-obvious test command. Nine tasks in three shapes, three each: add a CLI flag, add an endpoint, fix a seeded bug. Hidden tests are copied in after the agent stops.
  • Four arms per task, each in a fresh copy: cold (nothing), doc (a hand-written AGENTS.md, the control the critic asked for), facts (repo facts at session start only), full (facts plus the matching procedure at prompt time). Warm arms never see a procedure from the same task.
  • Runner today: claude -p --output-format json, which reports usage, turns, duration and cost. Runner at the venue: devin -p --export once Devin CLI is installed and logged in. Same hooks, same table.
  • Metrics: context tokens (input plus cache reads plus cache writes, summed over turns), output tokens, tool calls, calls before the first edit, turns, seconds, cost, tests pass. Mean and standard deviation reported. Fleet projection in tokens, minutes, ACU (15 minutes each) and dollars.
  • Improvement loop: read the warm traces, find what the agent still re-discovers, tighten extraction or injection, rerun. Stop when warm tool calls stop falling.

What the research and the critic said

Past HackMIT overall winners are human-scale stories with a live demo (a beehive, a wildfire claim, a bike route). A fleet chart does not win the overall prize. Sponsor prizes go to whoever leans hardest on the sponsor's own stack, and CLI or benchmark-shaped tools have won Cognition prizes elsewhere. Most likely wins: Cognition and The Token Company. Least likely: overall, and OpenAI.

The critic's five hits, all taken: Devin already auto-suggests Skills and Knowledge, so the pitch is "we keep Skills current from every harness, not only Devin sessions", not "memory for Devin". Devin bills in ACU, so the report shows minutes and ACU next to tokens. "Warm" is Cognition's word for sandbox pools, so the name changed. Two tasks per shape lets a reviewer say the warm run reused a near-duplicate, so it is three, and a static-doc control arm is in. Repeats and spread are reported.

Three booth questions for Cognition are in docs/critique-1.md, section 6. Ask them before the demo.

Open risks

  • Devin CLI is installed but not logged in. Until devin auth login runs, the eval runs on Claude Code with identical hooks. Then the same command with --runner devin.
  • Devin's hook payload has no transcript path and uses tool names exec and edit. The trace comes from the events themselves, so this is a name map, not a redesign.
  • Warm could not save much on tiny tasks. Discovery cost scales with repo size. The fixture must be big enough that discovery is real: a few hundred files, a non-obvious test command.
  • Judges may read it as a startup wrapper. Answer: new repo, new code, one disclosed optional adapter, and a number they can check in the results folder.
  • Devin said they are not interested in memory. The slide never says memory first. It says: sessions 2 to 9,000 cost this much less.
