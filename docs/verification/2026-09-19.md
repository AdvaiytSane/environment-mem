The reference runner created a disposable JavaScript retry-budget function with an off-by-one bug. The retained call IDs and observed exit codes matched the runner's independent ledger. These were real file/command operations with manually routed hooks; they were not tool calls made by a native coding agent.

At task stop, the branch forwarded the captured envelope through `store()` and `memorable ingest -` to the configured live extraction service at `memorable-extraction-api.memorable.workers.dev`. Credentials remained in process configuration. Memorable used a fresh, isolated **local** store. An independent `list --json` invocation found exactly one procedure:

`procedures/a6583d0d-refactor-retry-budget-calculation-logic`

The initial verifier stopped on the paraphrase failure. A later read-only continuation reused the same store and completed the remaining checks without submitting another trace. ## 3. Reproduce and inspect

Use Node 24+, an installed Memorable CLI, valid credentials and consent for one disposable trace. From this checkout:

```sh
HEADSTART_MEMORABLE_BIN=/path/to/memorable \
  node scripts/verify-memorable-live.ts --allow-live-write
```

For a Node-launched CLI, set `HEADSTART_MEMORABLE_BIN` to the Node executable and `HEADSTART_MEMORABLE_ARGS` to a JSON array containing the installed CLI entrypoint. The script reports its temporary artifact directory. It reads credentials from environment variables or the existing Memorable config without writing keys to the report. The explicit flag authorizes an actual service submission.

To rerun retrieval and hook-output checks against that already-created store without another submission:

```sh
HEADSTART_MEMORABLE_BIN=/path/to/memorable \
  node scripts/verify-memorable-live.ts --resume /path/to/previous/artifacts
```

The original `report.json` is retained; continuation writes `readback-report.json`. A paraphrase miss deliberately yields a nonzero exit and `partial_paraphrase_missed`. Extraction titles and identifiers may vary on a new run. The test has one stored procedure and is not a retrieval benchmark.

Independent consumer projects also installed the actual local checkout and a packed npm artifact. Both imported `headstart/memorable`, exposed `store`/`recall`, and ran the installed CLI. The packed artifact worked with installation scripts disabled. This caught and fixed a real packaging issue: Node refused TypeScript runtime entrypoints inside `node_modules`; the package now ships built JavaScript with source types. This was a local package installation, not an npm publication.

Local regression checks additionally cover task boundaries, repeated delivery, unknown outcomes, queue retry, safe installation and bounded subprocess failure. They support connector correctness, not native or hosted claims. Personal paths, account configuration, CLI notices unrelated to this fixture and the native authentication transcript remain outside this public repository.
